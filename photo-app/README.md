# 사진결 — 독립 로컬 MVP

T-260925-002. 인물·셀카 / 쇼핑몰 상품 / 음식·숙소를 하나의 계정·크레딧으로 사용하는 사진 보정 서비스. 가칭이며 공개 출시 전 버전이다.

## 실행

Node 22.13 이상(검증: 26.5), 단일 프로세스. 이 디렉터리는 기존 Astro 빌드·로고 Worker·홈페이지 경로에 연결되지 않는다.

```sh
cd photo-app
npm ci
npm start
# http://127.0.0.1:4387
```

다른 포트: `PORT=4388 npm start`. 데이터 위치는 `PHOTO_DATA_DIR`로 지정한다. 기본 `photo-app/data/`는 Git 제외이며 계정, 세션 해시, 원장, 사진을 SQLite에 저장한다. 데이터베이스 디렉터리 0700, 파일 0600. 같은 데이터베이스에 여러 프로세스를 띄우지 않는다. DB 접근을 직렬화하는 동기 트랜잭션과 로컬 작업 복구를 사용한다.

공개 네트워크 바인딩이나 외부 origin을 지원하지 않는다. 이는 상용 로그인·결제·개인정보·호스팅 검증 전 실행 범위를 코드로 제한한다. 공개 배포 설정으로 오해하지 않는다.

## 구현 범위

- 세 카테고리, 각각 세 스타일, 강도 1~100. sharp 기반 전체 밝기·채도 보정이며 AI 얼굴/객체 인식이 아니다. 상품 스타일은 채도를 바꾸지 않는다. 사진의 형태·텍스트·얼굴을 재생성하지 않는다. 보정 강도에 따라 보이는 색은 변하므로 동일 색상 보증을 하지 않는다.
- JPG/PNG/WebP, 단일 프레임, 입력 10MB·24MP 이하. EXIF 방향을 정규화하며 긴 변 최대 2400px PNG로 출력한다. 투명도 유지, EXIF/GPS 제거. 브라우저의 원본 파일은 수정하지 않는다. 서버는 정규화한 비교용 PNG와 보정 결과를 보관한다.
- 계정당 최초 3크레딧. scrypt 비밀번호 해시, 랜덤 세션의 SHA-256만 저장, HttpOnly/SameSite=Strict 쿠키. 로그인/로그아웃, 계정·사진 삭제. 로컬 미리보기용 아이디 가입이며 이메일 검증·복구는 미구현.
- 작업당 1크레딧을 트랜잭션으로 예약. 요청키+사진+옵션 지문을 대조해 재전송 시 추가 차감을 방지한다. 실패/프로세스 재시작 시 예약을 한 번만 환급한다. 완료 후 다운로드·ZIP·새로고침은 무료. 명시적 재보정은 새 요청으로 1크레딧.
- 동시 처리 전체 2개 / 계정당 1개. 브라우저 최대 10장 순차 처리. 인증 속도 제한, 동종 origin·Host 검사, 사진 소유자 검사, CSP, 파일 크기·디코딩 화소 한도.
- PNG 개별 다운로드, 20장·60MB 이하 ZIP 다운로드, 전후 슬라이더. 7일 결과 보관 후 프로세스 시작/분당 정리. 다운로드 시에도 만료를 차단한다. 운영 프로세스가 꺼져 있으면 다음 실행 때 삭제된다.
- 삭제는 사진 BLOB을 지우며 7일간 요청키 tombstone을 남겨 삭제 직후 동일 요청이 다시 차감되지 않게 한다. 계정 탈퇴는 관련 행 전체 삭제. DB secure_delete와 WAL truncate 적용. 외부 백업은 만들지 않는다. SSD 포렌식 삭제를 보장하지 않는다.

## BM 계약과 구현 경계

| 플랜 | 가격 초안 | 크레딧 | 상태 |
| --- | ---: | ---: | --- |
| 무료 | 0원 | 최초 3 | 실제 서버 원장 구현 |
| 충전팩 | 4,900원 | 30 | 가격표만, 판매 비활성 |
| 프로 | 월 19,900원 | 월 150 | 가격표만, 구독 청구 비활성 |

카테고리 공통 잔액이며 기본 보정 1크레딧. 생성형 기능은 3~5크레딧 검토안으로 실제 차감 경로가 없다. `/api/checkout`은 인증 후 항상 503을 반환한다. 유료 카드 버튼은 비활성이다. 화면에 원가 검증 전 가격안임을 표시한다. 결제 성공/구독 활성/충전 완료를 흉내 내는 고객용 흐름은 없다.

목표 변동원가 비율 30%는 검증 전 목표다. 실제 서버 선택, CPU·메모리·전송·저장·PG수수료·환급·지원비, 재시도율, 부가세 반영 후 순매출로 산정해야 한다. 현재 서버 보정은 유료 AI API를 호출하지 않지만 호스팅 원가가 0이라는 뜻은 아니다.

## 상용화 잔여

1. 대표적인 실제 인물/상품/음식/실내 사진으로 강도·색감·만족도 평가. 현재 회귀는 자체 제작 픽셀/정물 도형 입력이며 실제 피부 보정 품질 검증이 아니다.
2. 생성형 편집 공급자 선택·원가·약관/데이터 처리 확인·사용 승인 후 연동. 잡티 제거, 배경 교체, 원근 보정은 미구현. 로고 전용 Recraft 키·결제 승인 범위를 재사용하지 않는다.
3. 상용 인증(이메일 검증/복구·가입 남용 차단), 개인정보 고지/동의, 세션·백업 정책, TLS, 독립 호스팅·스토리지·작업큐 준비. 현재 로컬 서버를 그대로 인터넷에 노출하지 않는다.
4. Toss 새 상품/도메인 가맹범위 확인, 테스트 결제→서버 확인→지급→재전송/환불 검증. 충전 크레딧 유효기간·환불/차감 우선순위·소진 처리 확정. 프로의 월별 지급·갱신 실패·해지·환불·결제 웹훅 중복/순서 역전 구현. 스타일 저장과 팀 기능은 아직 제공하지 않는다.
5. 원가 실측으로 가격/크레딧 확정. 사용자 승인 후 공개 배포·판매 활성·실결제 검증. 현재 승인 범위는 로컬 구현·검증·PR이며 배포/새 비용/외부 문의 승인은 별도다.

## 검증

```sh
npm test
npm audit --omit=dev
# 저장소 루트에서 먼저 npm ci 후:
npx playwright test --config photo-app/playwright.config.mjs
# 선택: PHOTO_EVIDENCE_DIR=/absolute/path 로 화면 근거 출력 위치 지정
```

서버 검사: 세 카테고리 픽셀 변경·투명도/방향/크기, 지원 형식, 실제 PNG/ZIP, 차감/중복/환급, 잔액 소진, 동시 요청, 세션 복구, 계정 격리/CSRF/Host, 삭제/보관기간, 중단 환급. UI 검사는 모의 API 없이 데스크톱·모바일 Chrome에서 가입→실제 보정→전후 비교→PNG/ZIP→새로고침→삭제와 다중 업로드·실패 환급·판매 비활성을 확인한다. 테스트 계정·데이터·서버는 종료 때 정리한다. 별도 상시 서비스를 만들지 않는다.

기술 참조: [sharp operations](https://sharp.pixelplumbing.com/api-operation/), [Node SQLite](https://nodejs.org/api/sqlite.html). sharp는 0.35.4로 고정했다. 0.34.x에서 발견한 이미지 디코더 취약점을 해결한 버전으로 재검증한다.
